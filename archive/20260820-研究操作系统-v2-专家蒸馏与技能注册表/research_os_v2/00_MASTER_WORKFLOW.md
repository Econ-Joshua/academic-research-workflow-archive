# Personal Research OS v2.0：工作流与工作主线

## 1. 总目标

Research OS不是“自动写论文的Agent”，而是一个以人为最终研究主权者、以专家实践蒸馏为知识来源、以Skill为可复用方法单元、以Gateway为调度中枢、以多模型和Agent Runtime为执行基础设施的个人研究操作系统。

核心链条：

> 人类研究主权 → 真人专家实践 → 专家实践蒸馏 → 可复用Skill → Skill Registry → Method/Model/Runtime Gateway → Evidence与Validation → Human Checkpoint → Research Memory

## 2. 五层核心劳动分工

### A. Human Sovereignty：人类主权层

必须主要由研究者决定：

- Research Question
- Problem Significance
- Conceptual Lens
- Core Mechanism
- Contribution Positioning
- Evidence Standard
- Research Design Commitment
- Narrative Architecture
- Writing Taste
- Journal Positioning

AI可以提出、比较、攻击、模拟审稿人，但不得自动做最终commitment。

### B. Expert Practice Distillation：专家实践蒸馏层

目标不是复制专家的文字，而是从专家真实工作中提炼：

- 目标
- 输入
- 工作步骤
- 判断节点
- 判断规则
- 顺序与分叉
- 边界条件
- 失败模式
- 验证标准
- 停止条件
- 可迁移性

产出候选Skill，经人工批准后进入Registry。

### C. Skill Layer：方法能力层

Skill是“如何完成某类稳定研究任务”的可复用程序化知识单元。

Skill不等于Prompt。它必须包含触发、输入、步骤、边界、权限、工具、模型建议、验证、停止条件和禁止动作。

### D. Gateway/Orchestration：调度层

Gateway按顺序解决四个问题：

1. Method Routing：应该调用哪类研究方法/Skill？
2. Model Routing：用GPT、Claude还是Kimi等模型？
3. Runtime Routing：用Hermes、Codex/Claude Code、Python、Stata等执行器？
4. Validation Routing：如何验证结果，并在哪个节点交还人？

### E. Runtime：执行层

- Hermes：通用电脑与浏览器/文件执行
- Codex / Claude Code：代码工程与项目级修改
- Python / Stata / R：确定性计算与分析
- Web / PDF / 数据源：证据获取
- PowerShell：启动、环境管理和系统级胶水
- VS Code：开发、版本控制、项目管理

## 3. 核心原则

### 原则一：判断权与执行权分离

AI最适合扩大执行量与攻击强度；人最适合做价值判断与最终commitment。

### 原则二：方法先于模型

先决定“应该怎样做”，再决定“谁来做”。模型不能替代方法。

### 原则三：Skill先于Agent

不先设计超级Agent。先把稳定可复用的研究方法固化为Skill，再让Agent/Gateway组合这些Skill。

### 原则四：专家实践是最重要的高阶Skill来源

专家实践 > Agent产品机制 > 一般提示词技巧。后两者可以借鉴，但最终以专家实践为主。

### 原则五：证据优先

任何研究性输出都必须保留来源、证据位置、推理路径与验证状态。

### 原则六：所有高价值Skill都必须有边界

“什么时候不用”与“什么时候停止”与“怎么做”同样重要。

### 原则七：每次人工纠正都应成为潜在Research Memory

但必须经过归纳和验证后，才能升级为长期Skill；不能把一次性反馈直接当通用规则。

## 4. 从零到Research OS的主线

```text
第一阶段：建立目录与治理规则
    ↓
第二阶段：采集真人专家工作总结/案例
    ↓
第三阶段：Expert Practice Distillation
    ↓
第四阶段：形成Candidate Skills
    ↓
第五阶段：人工审核与版本化
    ↓
第六阶段：建立Skill Registry
    ↓
第七阶段：建立Evidence Store与Validation
    ↓
第八阶段：建立Method Router
    ↓
第九阶段：建立Model Router
    ↓
第十阶段：建立Runtime Router
    ↓
第十一阶段：组合成Orchestrator
    ↓
第十二阶段：在真实研究项目上运行、记录、修正
    ↓
第十三阶段：把高质量新经验再次蒸馏进系统
```

## 5. 系统真正积累的资产

不是聊天记录，不是模型账号，也不是某一个Agent。

真正资产是：

> Expert Practice → Distilled Procedure → Validated Skill → Skill Composition → Research Workflow → Research Memory

因此模型可以替换，Runtime可以替换，但核心研究能力资产不断复利。
