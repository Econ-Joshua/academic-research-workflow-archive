# 机制链模板（七环）

阅读本文前：SKILL.md 的 B 段需把论文理论拆成一条机制链。本模板给出七环定义、正向示例与常见失败模式。**缺环必须标"论文未说明"，不得用"因果感"脑补补齐。**

## 七环结构

```
初始条件 → 触发因素 → 核心机制1 → 核心机制2 → 组织/过程中介 → 结果 → 边界条件
```

| 环序 | 名称 | 定义 | 提问 |
|---|---|---|---|
| 0 | 初始条件 Initial condition | 使机制可能运转的存量/结构性前提 | "什么禀赋让它能发生？" |
| 1 | 触发因素 Triggering factor | 激活机制的启动事件/投入 | "什么事件把它点着？" |
| 2 | 机制1 Core mechanism 1 | 第一个能动的因果过程 | "第一个齿轮是什么？" |
| 3 | 机制2 Core mechanism 2 | 承接并转化的第二个过程 | "它如何放大/转化？" |
| 4 | 组织/过程中介 Organizational mediator | 组织内或时间上的承接体 | "靠什么结构/过程传导？" |
| 5 | 结果 Outcome | 被解释的核心结果 | "最终产生了什么？" |
| 6 | 边界条件 Boundary condition | 机制成立与否的外部/内部限定 | "什么条件下才成立？" |

## 正向示例（SMJ ByteDance 论文）

```
AI能力 + 结构相关数据（初始条件）
    ↓ 跨业务重复部署（触发）
自学习（机制1）
    ↓
交叉施肥 cross-fertilization（机制2）
    ↓
适应性组织设计（组织/过程中介）
    ↓
规模与范围同时扩张（结果）
    ↓
仅当业务共享可迁移数据结构时（边界条件）
```

## 好坏机制链对照

**好的机制链：**
- 每一环都有理论身份，不是同义反复（例如"A 导致 B，因为 B 由 A 导致"不是机制）。
- 有清晰的"能动的过程"，而非静态的相关性罗列。
- 边界条件能解释"为什么不是所有情境都如此"，这是理论强度的关键。
- 可被证据检验（呼应 C 段：机制是否有独立证据）。

**常见的坏链（记入 E 段批评）：**
- 环与环之间缺逻辑衔接，直接跳结果（机制缺失）。
- 中介只是"背景描述"，没有因果关系。
- 边界条件缺失 → 导致声称被 overstate（呼应 D 段）。
- 机制顺序有任意性，论文并未论证为何是这个次序而非别的。
- 把相关性当机制：报告了 A 与 C 相关，但永远没打开 A→C 的过程。

## 输出到 B 段时的要求

- 箭头必须可追溯回论文原文或合理推断（推断处标 `[?]`）。
- 若论文本身是黑箱（只报相关未给过程），B 段要明确写"论文未说明机制，实测为结果层面的证据"，不要替作者补机制。
- 产出机制链的目的，是让你自己的论文有可对照的机制设计基准——这也是 F 段"可迁移机制"的来源。
