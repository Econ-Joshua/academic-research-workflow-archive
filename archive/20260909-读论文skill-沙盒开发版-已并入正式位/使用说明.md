# 读论文 skill · 使用说明（给"你"看）

> v0.2 —— 从"摘要复述"升级为"智力机器拆解器"。本文是人读的介绍；SKILL.md 是给 agent 的执行指令。

## 它是干什么的

每次入库一篇论文，agent 按 SKILL.md 自动填论文页的【理解】段，产出一次**全量拆解**：不只是总结这篇论文讲了什么，而是把这篇论文里**可复用的智力机器**（招式、机制链、证据结构、写作结构、审稿人视角）拆出来，接回你自己的研究议程。

## 你拿到什么（【理解】段 9 项）

- **A 论文X光**：它在对抗什么（理论敌人）+ 用了哪招（招式表 8 招）
- **B 机制架构**：初始条件→触发→机制1→机制2→组织中介→结果→边界条件 七环
- **C 证据审计**：是支撑机制还是只支撑结果；最强/最弱证据
- **D 贡献拆穿**：作者声称 vs 实际证明，判断是否夸口
- **E 审稿人视角**：怀疑派审稿人会从哪里攻击
- **F 可迁移资源**：理论/机制/实证设计/变量构造/写作结构/批评 六项
- **G 连接候选**：≤5 行的"这篇论文能接到我研究议程哪里"
- **+ 术语定义、+ 开放 Puzzle**（喂 09 定稿蒸馏）

## 你需要手动维护的

1. **研究议程**（`知识库/研究议程.md`）：你的 5 个研究方向。议程变了，改这一个文件 → 对相关标签论文 `--rerun`，G 段自动重接。
2. **写作结构模板库**（`知识库/写作结构模板库.md`）：读到值得抄的写法，自己沉淀进库（格式见文件头）。

## 常用口令

| 你想做什么 | 怎么做 |
|---|---|
| 刷新全部论文【理解】 | 改完 skill 后 `python "<系统层>\SCRIPTS\paper-inbox.py" --project "<项目>" --rerun` |
| 只刷新某个方向 | 加 `--filter 标签`，省 token |
| 深入讨论某篇 | 正常讨论 → 有意义内容粘到【讨论】段 |
| 把某篇结晶 | 说"定稿 \<论文名\>" → 走 09-paper-finalize，G 段推演可在那里升格 |

## 和其它 skill 的分工

- 【讨论】【结论】段：本 skill 不碰（分别为人工策展 / 09 结晶）。
- 05-reviewer-attack：那是攻击你**自己的**理论；本 skill E 段是拆**别人的**论文。
- 03-knowledge-connection：跨论文/跨项目联想；本 skill G 段只做单篇内连接候选。
- 文风转换（英→中顶刊）：**不在本 skill**；只沉淀写作结构模板。
- 文献综述 skill：跨篇综述读多篇 paper-note（含本 skill 产出的【理解】段）。

## 常见问答

**Q 会不会每篇都跑太重？** 会，但有控：每段字数硬上限 + 不可得就写 `—` 不硬凑 + rerun 可用 `--filter` 限定范围。重读靠 `--rerun` 整批刷新，量大的项目分标签做。

**Q 为什么要单次通读而不是拆子代理？** 7 个 agent 各读一遍 = 7 倍 token，且步骤强依赖难并行、拼接易失连贯。所以拆成 7 个**知识库**而非 7 个 agent。

**Q G 段会不会"越界"？（它看起来像联想/结论）** 刻意降级过：只指相关性、标 AI 初读、限 5 行，不下"有用"结论。完整推演留给【讨论】与 09 定稿——那里有人裁决。
