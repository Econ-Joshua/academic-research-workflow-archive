# 读论文 skill（产出【理解】段 · 智力机器拆解器）

> 固定 skill。**由你手动迭代**。v0.2 起从"摘要复述"升级为"智力机器拆解"：不总结论文，而是把每篇论文转成你自己的理论资源、机制设计基准与写作参照。每次改完 `paper-inbox.py --rerun` 整批刷新【理解】段。

## 功能定位

把一篇论文的**可复用智力机器**拆出来。这台机器可能是：一组概念、一套机制链、一个因果架构、一次理论重构招式、一种实证识别策略、一个写作结构、一句经得起审稿人的贡献陈述。拆出来后，论文进入你自己的理论工具箱。

**本 skill 是单篇论文层（L1）静态理解**，下游由 09 定稿结晶、由文献综述 skill 跨篇综述。

## 输入

- 论文源：`<项目>/INBOX/<源文件>` 或 `source_url` 指向的链接
- 论文页骨架：`<项目>/memory/literature/note-<标题>.md`
- 知识库研究议程：本 skill `知识库/研究议程.md`（决定 G 段连接候选的目标，可独立维护）

## 输出（写入【理解】段）

一次全量拆解，产出 7 个主段 + 2 个保留项，每段**设字数上限**，宁缺毋滥：

| 段 | 内容 | 字数上限 | 加载知识库 |
|---|---|---|---|
| A. 论文X光 | 核心现象 / 理论敌人 / 理论招式 | 300 | 理论招式表.md |
| B. 机制架构 | 七环链条 | 300 | 机制链模板.md |
| C. 证据审计 | 证据类型 / 支撑机制还是只支撑结果 / 最强最弱 | 250 | 证据审计清单.md |
| D. 贡献拆穿 | 作者声称 vs 实际证明（两版） | 150 | — |
| E. 审稿人视角 | 最可能被攻击点 / 替代解释 / 概念精度 | 250 | 审稿人攻击模式.md |
| F. 可迁移资源 | 理论/机制/实证设计/变量构造/写作结构/批评模式 六项 | 300 | 写作结构模板库.md |
| G. 连接候选 | ≤5 行，指向自己的研究议程 | 100 | 研究议程.md |
| + 术语定义 | 关键概念的精确定义与上下文 | 150 | — |
| + 开放 Puzzle | 未解决谜题 / 局限（供 09 蒸馏） | 150 | — |

> 每段若有内容确不可得（如纯理论论文无实证），写 `—`（无），**不得编造留空**。

## 拆解流程（一段通读后按序产出）

一次通读论文，按其结构依次填上述 9 项。步骤间有强依赖（机制依赖招式、贡献依赖机制），**不拆子代理、不重复读**：

1. 识别核心现象与理论敌人 —— 这篇论文在**对抗什么**？（反例：无敌人的论文往往是描述性）
2. 判定理论招式 —— 对照招式表，主招式限 1-2 个，注明主次。
3. 重构主论证 —— 中心主张 / 关键概念 / 概念间关系（作为 B、D 的底板）。
4. 拆解机制架构 —— 按七环模板，缺环注明"论文未说明"。
5. 审计证据 —— 区分"支撑机制"vs"只支撑结果"。
6. 分离声称与实际贡献 —— 作者claim 一句 / 实际证明一句，判断是否overstate。
7. 审稿人视角批判 —— 一个怀疑的 AMJ/SMJ/ASQ/MS 审稿人会攻击哪？
8. 提取可迁移资源 —— 六项，每项 1-3 行。
9. 输出连接候选（G）—— 仅指出与该论文结构相关的研究议程点，**不下"有用"结论**，标注 AI 初读；完整应用推演留给【讨论】段与 09 定稿。
10. 补术语定义与开放 Puzzle（供 09 蒸馏）。

## 边界（关键）

- 【理解】= **静态**初读，只由本 skill 产出与修正，不随讨论改动。
- 【讨论】= 活的，人工策展，本 skill **不碰**（G 段推演、跨模型分歧记这里）。
- 【结论】= `09-paper-finalize` 定稿时结晶，本 skill **不产出**。
- **与 05-reviewer-attack 分工**：本 skill E 段是审稿人视角拆**别人的论文**（提取攻击模式作资源）；05 是对抗角色攻击**你自己的理论**。对象不同，不得互替。
- **与 03-knowledge-connection 分工**：本 skill G 段只做单篇内的连接候选；跨论文/跨项目联想归 03 与联想登记簿。
- 写作翻译能力（AMJ/SMJ→《中国工业经济》/《管理世界》文风转换）**不在本 skill**，只提取写作结构模板进知识库，翻译转换归 04 或将来独立 skill。

## 刷新协议

1. 修改本 skill（迭代规范或知识库）。
2. 跑 `python "<系统层>\SCRIPTS\paper-inbox.py" --project "<项目>" --rerun`（可加 `--filter 标签`）→ 重置全部(或指定)论文页【理解】段为占位。
3. 让任一 agent 按新版本对每篇重跑填【理解】。
4. 跑 `python "<系统层>\SCRIPTS\paper-check.py" --project "<项目>"` 校验三段制结构未破坏。
5. 知识库仅改 `研究议程.md` 时，可用 `--filter` 只重刷相关标签的论文，省 token。

## 反幻觉质量门

- 外部论文数据不核实不写入；机制链缺环、概念定义不明处用 `[?]` 或"论文未说明"标注，绝不编造。
- 每段字数上限为硬约束；宁可精简，不可灌水。

## 不参与自动迭代

本 skill 不进 `07-meta-review`、不写入 `_log.md` 触发修订；迭代权完全在你，AI 只按当前版本执行。
