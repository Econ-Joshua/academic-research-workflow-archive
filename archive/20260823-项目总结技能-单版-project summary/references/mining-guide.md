# 提炼标准与写作模板（mining-guide）

本文件是 distill-skill 的判断细则。第 3 步"复用性判断"和第 4 步"撰写正文"时必读。

## 一、复用性四问（判断细则）

对 shortlist 中每个候选逐项回答，**≥3 个"是"才沉淀**：

| # | 问题 | "是"的判据 | "否"的判据 |
|---|---|---|---|
| 1 | 跨场景通用吗？ | 去掉项目名/私有路径/特定表名后，别的工作还能用 | 逻辑绑死某个项目的数据结构 |
| 2 | 重新发现成本高吗？ | 含踩坑、隐蔽依赖、调参结论、多步顺序；当时花了对话 2 轮以上才跑通 | 一条常识命令、google 首条结果 |
| 3 | 稳定可复现吗？ | 确定性操作，重放可得到同样结果 | 依赖当天临时状态、一次性数据、未验证猜测 |
| 4 | 能部分脚本化吗？ | 存在确定性步骤可抽成脚本/命令 | 纯主观判断（此类走"规范决策型"正文沉淀，不打"是"） |

补充信号：
- **出现频次 ≥2**（digest 的 occurrences 字段）是强信号：说明用户反复需要它。
- **error_fix 候选**天然满足第 2 问：踩过的坑就是最贵的经验。
- shortlist 的 `score` 只是初筛，最终以四问为准；低分但四问全"是"的也要保留。

## 二、什么不值得沉淀（负例清单）

- 只出现一次、无通用性的业务代码。
- 包含真实密钥/内网地址且无法脱敏的内容（脱敏后失去意义的，放弃）。
- 未经用户确认的猜测性结论。
- 纯数据产物：表格、路径清单、某次运行输出。
- 官方文档已有的一句命令（如 `pip install xxx`），除非组合成了多步流程。
- 一次性的迁移/重命名脚本，目标文件以后不再存在。

## 三、类型判定与产出形态

| 类型 | 判据 | 产出形态 |
|---|---|---|
| 脚本工具型 | 候选代码 runnable=true，或可改写为独立程序 | `scripts/*.py`（零 token 执行）+ 正文只写触发/参数/示例 |
| 流程型 | 多步骤、有顺序依赖、含易错点 | 正文写编号步骤，每步一条可复制命令 |
| 规范决策型 | 命名、目录组织、技术选型类约定 | 正文写规则表 + 正反例各一条 |
| 领域知识型 | 报错-修复对、疑难排障 | 正文写"症状 → 原因 → 解法"条目 |

一个候选可能同时是"流程 + 脚本"：流程正文 + 把其中确定性步骤抽成脚本，这是最优形态。

## 四、SKILL.md 正文写作模板

frontmatter 规范（Kimi）：`name`、`description` 必填；`whenToUse` 建议必写；正文可用
`${KIMI_SKILL_DIR}`（技能目录绝对路径）和 `$ARGUMENTS`（调用参数）。

```markdown
---
name: <kebab-case-动词-名词>
description: <一句话功能>。当<触发场景>时使用。
whenToUse: <更详细的触发场景，含用户会说的关键词>
---

# <技能名>

<两三句话说清解决什么问题、适合谁、产出什么。>

## 何时使用
- <场景1（用户会说的话）>
- <场景2>

## 使用方法
<脚本工具型：>
    python "${KIMI_SKILL_DIR}/scripts/<脚本>.py" <参数>
    参数说明表：| 参数 | 必填 | 说明 |
<流程型：编号步骤，每步一条命令 + 一句"为什么这步容易错">

## 注意事项
- <边界：什么情况不适用>
- <已知限制>

## 示例
<一个最小可运行的完整例子（脱敏后）>
```

写作要求：
- description 必须含触发条件，写用户会说的原话关键词（中文技能写中文触发词）。
- 步骤命令必须可整行复制执行，不留"xxx""等等"这类占位。
- 每个脚本在正文中至少出现一次完整调用示例。
- 篇幅克制：正文 30-120 行为宜，细节放 `references/`。

## 五、脚本化改写清单

把对话中的代码块改写为可独立运行脚本时逐项核对：

1. **纯标准库**：不依赖 pip 安装的第三方包（做不到就在正文显著位置写明依赖与安装命令）。
2. **argparse 接口**：所有输入走参数或 `-o` 输出文件，不硬编码路径；提供 `--help`。
3. **无副作用默认**：默认只读；写文件/删除操作必须显式传参触发。
4. **退出码**：0=成功，非 0=失败；错误信息写 stderr。
5. **跨平台**：路径用 `pathlib`，不用 `;` 链接命令，编码显式 `utf-8`。
6. **脱敏**：删掉真实 key/路径/域名，用环境变量 `os.environ.get('<NAME>')` 或 `<占位符>`。
7. **截断防护**：处理用户数据的脚本要限制最大读取量，防止巨文件拖死。

## 六、脱敏清单（写完自查）

- [ ] API key / token / 密码（validate 会扫）
- [ ] 内网域名、IP、内部仓库地址
- [ ] 本机绝对路径（`C:\Users\...`、`/home/...`）→ `<PROJECT_DIR>`
- [ ] 真实人名、公司名、项目代号
- [ ] 一次性数据（当天的输出、临时表、日志片段）

## 七、命名规范

- 全小写 + 连字符：`pdf-extract-tables`、`deploy-static-site`、`python-env-triage`。
- 动词-名词结构优先；领域排障类可用"名词-triage/fix"。
- 名字要说"做什么"而不是"怎么做"：`batch-resize-images` 优于 `pil-loop-resize`。
